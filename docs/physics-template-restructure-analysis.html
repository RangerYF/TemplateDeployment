1

用户痛点分析

在上周的物理学科教师回访中，多位一线高中物理教师反馈了使用模板时遇到的核心问题。以下从教师的实际操作路径出发，逐一还原痛点。

1.1 操作路径冗长：从打开到开始教学需要7步

以"给学生演示斜面受力分析"为例，教师的实际操作路径为：

  1. 打开力学模板 → 进入模块选择Hub页面
  2. 在6个模块（力分析/运动/振动/波动/动量/能量）中找到"力分析"
  3. 进入模块概览，选择具体场景
  4. 进入场景编辑器界面
  5. 从左侧物体库中拖拽物体（方块/球体/锚点等7种）到画布
  6. 在右侧属性面板中逐一配置参数（质量、摩擦系数、弹性、尺寸、速度xy、角度、位置xy等12+个字段）
  7. 从编辑模式切换到运行模式，点击播放

教师期望的操作路径应为：打开 → 选预设 → 调参 → 运行，3步以内完成。当前流程中有4步属于"工具学习成本"而非"教学操作"。

1.2 参数暴露过多：无法区分哪些影响教学

以力学模板的属性面板为例，一个物体的可配置参数包括：

参数教学相关性教师是否需要调整
质量核心几乎每次都调
斜面角度核心几乎每次都调
摩擦系数核心经常调
初速度场景相关部分场景需要
弹性系数高级偶尔调
物体宽度/高度无关几乎不调
速度y分量无关几乎不调
精确位置x/y无关从不调
锁定旋转无关从不调
材质类型无关从不调

12个参数中仅3个是核心教学参数，其余大部分与教学无关。教师面对全部暴露的参数面板，无法快速判断"哪些需要关注"。

1.3 跨模板操作不一致：换模板要重新学习

5个物理模板在交互方式上存在显著差异，教师在不同模板间切换时需要重新适应：

交互元素力学模板统一模拟器光学热学天体

参数调整方式右侧滑块面板右侧面板+画布拖拽左侧控件左侧面板右侧折叠区

1.5 痛点总结

四大核心痛点的根源是同一个问题：当前模板按"场景编辑器"的思路设计，面向的是模板开发者而非一线教师。左侧物体库、多种工具模式、完整的撤销重做系统、十余个内部状态管理模块 —— 这是专业创作工具的架构，不是课堂教学演示工具应有的复杂度。教师需要的是"选场景 → 调参数 → 看效果"的简洁流程，而非从零搭建物理场景的全功能编辑器。

重构方案对比与选择

基于用户痛点和竞品分析，我们提出两条重构路径，并评估后推荐最终方案。

方案 A：在现有模板上渐进优化

保持现有5个仓库的架构不变，通过参数精简、UI统一和视觉升级来改善体验

方案A核心思路

  • 参数精简：审查每个子模板的所有参数，删除无用参数，将剩余参数分为"核心"和"高级"两层，默认只展示3-5个核心参数
  • UI统一：提取共享UI组件库，统一播放控制位置、参数面板样式、结果展示方式
  • 视觉升级：引入共享渲染增强工具包，提升Canvas渲染品质（添加渐变、光影、粒子效果）
  • 导航简化：将力学模板的3层导航（Hub→模块→场景）简化为Tab直达

优势

  • 改动范围可控，风险低
  • 不影响已有部署和bridge协议
  • 每个模板可独立改造、独立上线
  • 开发周期短（1-2周可出首个改造模板）

劣势

  • 粒度问题无法解决 — 一个应用内仍需多场景切换
  • 技术栈碎片化（4种框架）无法统一
  • 长期维护成本未降低
  • 与行业竞品的粒度设计不对齐
  • 新模板开发仍需从零构建UI+渲染

方案 B：构建全新细粒度场景化模板体系

对齐竞品设计范式，全新构建细粒度场景化模板体系，每个模板只聚焦一个具体的教学实验场景

方案B核心思路

  • 细粒度拆分：一个模板 = 一个教学场景（如"斜面受力分析"、"串联电路"），打开即进入实验
  • 共享核心库：构建统一的UI组件库、渲染引擎、模板外壳，所有场景模板共用
  • 复用物理引擎：从现有模板中提取物理计算代码（planck-js封装、RK4求解器、轨道力学等），集成到新架构
  • 统一技术栈：React + Zustand + Canvas 2D / Three.js，消除技术碎片化
  • 视觉品质统一：统一渲染引擎，确保所有模板达到一流视觉标准

优势

  • 从根本上解决粒度问题，与竞品设计对齐
  • 打开即用，操作流程从7步降至3步
  • 统一技术栈，消除碎片化
  • 共享库复用率极高，新增模板只需写场景配置
  • 长期维护成本大幅降低
  • 前端品质、渲染效果可从零设计到一流

劣势

  • 前期工程量较大（需构建共享库+拆分场景）
  • 需为新模板定义新的snapshot结构
  • 平台侧模板注册需配合调整

4.2 推荐方案

推荐策略：旧模板保留优化 + 全新构建方案B模板体系

综合评估后，推荐以方案B为核心方向：现有模板按用户反馈做基础优化后保留（面向进阶用户和沙盒需求），同时全新开发一套细粒度场景化模板体系。新模板复用旧模板中高价值的物理引擎代码，前端从零设计，品质大幅提升。

选择理由：

  1. 方案A无法解决核心矛盾 — 即使参数精简，一个应用内6个场景的切换复杂度仍然存在，这是老师反馈"像编辑器"的根本原因
  2. 方案B对齐行业验证过的设计范式 — PhET、火花、NOBOOK三家无一例外采用一模板一场景的粒度
  3. 旧模板保留避免风险 — 不碰已上线的功能和数据，旧模板继续服务进阶用户；新模板做好一个上一个
  4. 物理引擎代码直接复用 — 旧模板最有价值的资产（物理计算逻辑）不需要重写，直接提取到新架构
  5. 从零设计前端更高效 — 不受旧模板4种技术栈的约束，统一用现代技术栈构建高品质前端

5.2 模板拆分标准

拆分的核心原则是"一个模板 = 一个教师可以独立讲授的具体教学场景"。具体判定标准如下：

标准满足不满足
单一物理场景斜面受力分析、薄透镜成像、串联电路力的分析与合成（含斜面/悬挂/共点力多场景）
无需场景切换打开即进入目标实验，无选择页需要从列表/Tab中选择具体实验
核心参数 ≤ 5个质量、角度、摩擦系数（3个）同时涉及力学+运动+能量等多维参数
教学目标单一理解斜面上的力分解既要讲力分解又要讲运动规律又要讲能量守恒
30秒上手教师30秒内能理解所有控件并开始演示需要学习工具模式、导航层级、对象拖拽

拆分粒度示例

以当前力学模板（phys_template_mechanics）为例，按上述标准应拆分到具体场景级别：

当前子模板当前包含的场景拆分后应为独立模板
P-01 力的分析斜面受力分析独立模板
悬挂体受力分析独立模板
共点力合成独立模板
力的平衡独立模板
P-02 运动匀变速直线运动独立模板
抛体运动独立模板
圆周运动独立模板

以此类推，其余子模板均需按具体教学场景逐一拆分。

拆分规模估算

按照上述标准，现有5个物理应用预计拆分为40-60个独立场景模板（具体数量需根据课标知识点逐一梳理后确定）。每个模板仅包含3-5个业务文件，依赖共享核心库运行。

具体的拆分清单将在开发启动时，结合高中物理课标知识点和现有模板内置场景逐一梳理确认。同时保留一个 P-Sandbox（物理沙盒）模板，承载自由搭建能力，面向有进阶需求的教师。

5.5 物理计算架构：公式直算 + 引擎模拟双模式

现有力学模板基于通用物理引擎 Box2D/planck-js 构建，该引擎按真实世界规律模拟物理行为。但高中物理教学中大量使用理想化条件（光滑平面、完全弹性碰撞、轻绳不可伸长、理想气体等），通用引擎难以精确实现这些设定，导致教师反馈仿真结果与教科书公式不一致。

新架构的 @edumind/physics 包提供两种计算模式，按场景需求选用：

模式原理适用场景特点
公式直算 直接用物理公式计算结果
F=ma, E=mgh, p=mv, T²=4π²r³/GM 等		 大部分教学场景（力分析、运动、能量守恒、电路、天体等） 结果100%匹配教科书；支持理想化条件（无摩擦、完全弹性等）；参数变化即时出结果
引擎模拟 调用 planck-js 等物理引擎
做实时刚体/碰撞/约束模拟		 需要真实物理行为的特殊场景（多体碰撞演示、复杂约束系统、物理沙盒） 行为逼真；支持自由搭建；但无法保证与教科书公式精确一致

设计原则：教学场景默认使用公式直算模式，确保物理精准性和教科书一致性。引擎模拟模式仅用于沙盒和需要真实碰撞效果的特殊场景。两种模式共用同一套渲染管线，教师无感知差异。

现有代码资产的复用策略

资产策略原因
RK4 数值求解器直接复用通用数值求解，与引擎无关，公式直算模式的核心工具
轨道力学计算直接复用自研代码，按公式计算，天然支持理想设定
Canvas 渲染技术参考重建渲染思路（径向渐变/bloom/3D质感）可复用，需适配新架构
planck-js 力学模拟场景化决策沙盒和碰撞演示场景保留使用；理想化教学场景改用公式直算
EM 域注册体系参考架构实体-求解器-渲染器的模式可借鉴，但代码耦合度高需重写
UI 组件代码重新构建跨模板重复率50%但质量参差，不如统一重建

5.6 参数分层策略

层级规则举例（斜面受力）展示方式
核心参数直接影响核心物理现象，不超过5个质量、角度、摩擦系数、显示分力默认展示，滑块+数值
高级参数影响细节，不影响核心理解弹性系数、重力加速度、空气阻力"高级设置"折叠区
删除参数纯技术/调试用，与教学无关物体宽高、精确坐标、材质、锁定旋转直接移除

技术角色适用场景

风险与缓解

风险影响概率缓解措施

低端校园设备性能不足高中GPU能力检测+Canvas 2D降级方案；在真实校园硬件上测试
新旧模板并存期间snapshot不兼容中低新模板定义新的snapshot schema；旧模板保留作为fallback
2周工期紧张中中共享库架构设计精简，不过度抽象；AI辅助开发提升效率；新模板做好一个上一个
总结

本方案通过"保留旧模板 + 全新构建场景化模板体系"的策略，在不影响现有功能的前提下，从根本上解决教师反馈的四大痛点 —— 模板粒度过大、参数过载、操作不一致、视觉品质不够。新体系复用旧模板的物理引擎资产，采用统一的Canvas/Three.js高品质渲染引擎和标准化的UI组件库，实现"打开即用、3步操作、一流视觉"的目标。物理部分计划2周内完成全量上线，完成后可直接扩展至化学和数学学科。
