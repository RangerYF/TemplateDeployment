## 二、反馈逐条回应

### 反馈①：古典模型「加入数据处理过程展示」

#### 用户原话
> 抛硬币、掷骰子、两骰子点数和和摸球问题等概率模拟器整体挺好的，但在日常的教学中，不止只有频率分布直方图一种表格，同时希望可以加入数据处理的过程，现阶段只是动态图像的展示，并没有数据的变化，在多次模拟的同时可以加入实验结果的展示。

#### 实现方案
新建共享组件 `TrialDataTable`，在 4 个古典模型的 Renderer 主图右侧加入一张「实验数据表」：
- **表格列**：结果 / 频数 / 频率 / 理论概率（四列对照）
- **响应动画进度**：表格内容随 `displayedN`（当前已观测次数）实时变化，让学生看到数据如何逐步累积、频率如何向理论概率收敛
- **viewBox 适配**：原图保持不变，整体 viewBox 向右扩宽 200–280px 容纳数据表

#### 文件清单
- 新增：`src/components/scene/renderers/TrialDataTable.tsx`
- 修改 viewBox + 集成数据表：
  - `src/components/scene/renderers/CoinFlipRenderer.tsx`（VW 800→1020）
  - `src/components/scene/renderers/DiceRollRenderer.tsx`（VW 800→1100，事件面板下移）
  - `src/components/scene/renderers/TwoDiceSumRenderer.tsx`（VW 900→1140）
  - `src/components/scene/renderers/BallDrawRenderer.tsx`（VW 800→1040）

#### 用户操作流程
1. 顶部菜单选择「古典概型 → 抛硬币 / 掷骰子 / 两骰子点数和 / 摸球问题」
2. 在右侧参数面板设置 n、点击「运行模拟」
3. 切换到「多次模拟」标签 → 点击「动画播放」
4. 主图右侧数据表随动画同步刷新（频数 / 频率持续变化）

### 反馈③：【新增】三人羽毛球累负淘汰赛（2020 新高考 Ⅰ）

#### 用户原话
> 高中数学中常出现比赛类的赛制问题，特别是轮空类，不知道能不能直观展示出来，例如 2020 年新高考卷的统计题，学生对这种实验的运行就比较不容易理解。
> 甲、乙、丙三位同学进行羽毛球比赛，约定赛制如下：累计负两场者被淘汰，比赛前抽签决定首先比赛的两人，另一人轮空。每场比赛的胜者与轮空者进行下一场比赛，负者下一场轮空，直至有一人被淘汰；当一人被淘汰后，剩余的两人继续比赛，直至其中一人被淘汰，另一人最终获胜，比赛结束。

#### 实现方案

##### 1. 完全可扩展的事件追踪架构
针对用户「希望可扩展性强一点，能不能抽取一套架构让教师可以填入具体设置」的明确诉求，设计如下：

- **可调三方胜率**：分别设置「甲胜乙」「甲胜丙」「乙胜丙」三个独立概率（默认 0.5 公平赛）
- **预置事件库 `TOURNAMENT_EVENTS`**：12 个原子事件，教师在 Inspector 中勾选要追踪哪些，每个事件包含 `id / label / predicate / theoreticalProb?`
  - 甲 / 乙 / 丙 最终获胜（理论 9/32, 9/32, 7/16）
  - 甲 / 乙 连胜四场（理论 1/16）
  - 恰好需要 3 / 4 / 5 / 6 / 7 场比赛
  - 不超过 5 场 / 至少 5 场
- **未来扩展只需在 `TOURNAMENT_EVENTS` 数组追加一项**：`{id, label, predicate, theoreticalProb?}`，无需修改渲染器和 Inspector

##### 2. 泳道树状图（核心可视化）
为更清晰展现「每场比赛的轮空、晋级、对决」三种关系，主可视化采用**泳道流程图**而非传统二叉树（线性单链赛事不适合二叉树）：

- **三条横向泳道**：甲（绿）/ 乙（蓝）/ 丙（橙），最左带玩家姓名标签
- **X 轴 = 比赛场次**
- **节点语义**：
  - 实心大圆 = 该玩家本场出战并**胜**
  - 描边大圆 = 该玩家本场出战但**负**（节点下显示「累 N 负」）
  - 灰色小点 = 该玩家本场**轮空**
  - 红边圆 + ✗ = 该玩家累计 2 负已被**淘汰**
- **连线语义**：
  - 灰色垂直虚线 = **同场对决**（连接每场比赛的两个出战玩家）
  - 玩家色实线（粗）= **胜者晋级**到下一场对决
  - 玩家色短虚线 = **败者下一场轮空**
  - 玩家色点线 = **轮空者下一场上场**（替补机制）
- **终局标识**：冠军节点旁标 ★ 与「X 冠军」文字

##### 3. 其他统计可视化（下半部分）
- **冠军频率分布**：甲/乙/丙 三色横向条形图
- **总场数分布**：恰好 4 场 / 5 场 / 6 场等的频率柱状图
- **追踪事件对比**：每个勾选事件显示「模拟频率柱 + 理论概率红线」（仅 0.5 对称胜率时显示理论值）

#### 文件清单
- 引擎：`src/engine/simulations/tournamentMatch.ts`（含 `simulateOneTournament` + `runTournamentMatch` + `TOURNAMENT_EVENTS` 事件库 + `TournamentEventDef` 接口）
- Renderer：`src/components/scene/renderers/TournamentMatchRenderer.tsx`（含 `computeLaneStates` helper + 泳道树状图绘制）
- Inspector：`src/components/panels/inspectors/TournamentMatchInspector.tsx`（含三方胜率滑块 + 事件多选 + 重置公平赛按钮）
- 类型：`src/types/simulation.ts`（`TournamentMatchParams` + `TournamentEventId` 联合）

#### 用户操作流程
1. 顶部菜单 → 古典概型 → 三人羽毛球赛
2. 右侧 Inspector：
   - 调整模拟轮数 n
   - 调整三个胜率（默认 0.5 / 0.5 / 0.5 公平赛）
   - 勾选要追踪的事件（默认勾选 5 个）
3. 点击「运行模拟」
4. 上方泳道图显示第 1 次模拟的赛程；下方三块统计图汇总 n 次模拟的结果

#### 数据契约验证（2M 次 Node 模拟）
| 事件 | 模拟频率 | 理论值 | 偏差 |
| --- | --- | --- | --- |
| 甲连胜四场 | 0.06217 | 1/16 = 0.0625 | -0.0003 |
| 丙最终获胜 | 0.43805 | 7/16 = 0.4375 | +0.0006 |
| 甲最终获胜 | 0.28051 | 9/32 = 0.28125 | -0.0007 |
| 乙最终获胜 | 0.28144 | 9/32 = 0.28125 | +0.0002 |
| 恰好 4 场结束 | 0.25030 | 1/4 = 0.2500 | +0.0003 |
| 恰好 5 场结束 | 0.74970 | 3/4 = 0.7500 | -0.0003 |

全部数值偏差小于标准差量级，算法正确。

### 反馈④：【新增】双盒互换球

#### 用户原话
> 摸球实验中有一类放入对方盒子的题目，不知道是否能够展示。
> 甲、乙两个盒子中分别装有大小、形状、质地相同的 1 个黑球和 2 个红球。现从两个盒子中各任取一个球放入对方盒子中称为一次操作，重复进行 n 次操作后，甲盒子中有 0 个黑球，1 个黑球，2 个黑球分别记为事件 An、Bn、Cn。

#### 实现方案

##### 1. 完全参数化
- **每盒初始黑球数**（1～5）+ **红球数**（1～8），不限于题目默认 1 黑 + 2 红
- **操作次数 n**（1～30）：每轮做几次互换
- **模拟轮数**：累计观察分布

##### 2. 三块可视化
- **操作快照（教学核心）**：展示第 1 次模拟的前 6 步操作快照。每步显示甲乙盒此时的球（黑 / 红圆点可视化）+ 取出的球颜色 + 互换箭头
- **甲盒黑球数频率分布**：柱状图标注 An（0 黑）/ Bn（中间黑数）/ Cn（最大黑数），叠加理论 P(Bₙ) 红色虚线
- **甲盒黑球数均值轨迹**：折线图展示从操作 0 到操作 n 的均值变化，标注稳态参考线（=initBlack）

##### 3. 理论公式对照
在默认 1 黑 + 2 红 配置下，引擎自动计算并显示：

```
P(B_n) = 3/5 + (2/5) · (-1/9)^n
```

Inspector 中给出友好提示，渲染器底部显示完整公式。其他配置下不显示理论值（避免误导）。

#### 文件清单
- 引擎：`src/engine/simulations/boxSwapBalls.ts`（含 `simulateBoxSwapTrial` + `runBoxSwapBalls` + `theoreticalBn` 函数）
- Renderer：`src/components/scene/renderers/BoxSwapBallsRenderer.tsx`（含 `renderBoxBalls` SVG 球可视化 helper）
- Inspector：`src/components/panels/inspectors/BoxSwapBallsInspector.tsx`（含 1 黑+2 红 配置识别提示）
- 类型：`src/types/simulation.ts`（`BoxSwapBallsParams`）

#### 用户操作流程
1. 顶部菜单 → 古典概型 → 双盒互换球
2. 默认参数即为题目配置（1 黑 + 2 红，4 次操作），直接「运行模拟」
3. 修改参数后会看到操作快照、频率分布、均值轨迹全部变化

#### 数据契约验证（2M 次 Node 模拟）
| n | 模拟 P(Bₙ) | 理论 P(Bₙ) |
| --- | --- | --- |
| 1 | 0.55521 | 5/9 = 0.55556 |
| 2 | 0.60465 | 49/81 = 0.60494 |
| 4 | 0.60036 | 0.60006 |
| 10 | 0.59994 | 3/5 = 0.60000 |

P(B₁) = 5/9 完美对应题目 A 选项；P(Bₙ) 公式完美对应 D 选项。

## 三、教学体验优化追加项

### a) 摸球去掉教学增强面板（用户原话「摸球的时候去掉这个面板吧」）
原 `TeacherEnhancementOverlay` 在摸球时显示「课堂场景预设 / 目标对象命名 / 模型判断」面板，用户希望取消。

### b) 线性回归教学输入内聚到 Inspector（用户原话「把面板的功能融合到右侧栏，不要单独开一个面板覆盖下面的信息」）
将「预设数据集 / 教师输入二维数据 / X-Y 轴标签 / 当前数据预览」全部搬入 `LinearRegressionInspector`，原浮层面板整体删除。

**实现做法**：
- 完全重写 `LinearRegressionInspector.tsx`，加入「预设数据集 / 教师输入」二态切换
- 教师输入态：X/Y 轴名称双 input + 二维数据 textarea（每行一组 x,y）+ 当前数据预览
- 删除 `TeacherEnhancementOverlay`（旧文件 285 行 → 新 main.tsx 仅 12 行）
- 清理 main.tsx 所有相关 imports

### c) 扇形图 legend 行高重叠修复（用户反馈「各分组占比和下面的项目重叠了」）
- `LEGEND_ROW_H` 由 30 → 44
- 新增 `LEGEND_LABEL_GAP = 18`
- viewBox 高度 540 → 580 容纳更大行高
- 第二行（频数·频率）相对第一行（区间 label）的 y 偏移由 14 → 22

### d) AiOperations 类型修复（部署到 Vercel 时触发的 4 个 tsc 错误）
v0.3 类型扩展导致 `aiOperations.ts:mergeParams` 缺少新 case + 旧字段类型不匹配。

**修复方式**：
- ballDraw case 补 `scenarioId / targetLabel / otherLabel`
- linearRegression case 补 `dataSpec`
- 新增 4 个 case：`pieChart / lineChart / tournamentMatch / boxSwapBalls`
- 补充类型 imports 与 `TOURNAMENT_EVENTS` 引用

## 六、备注与未来可扩展点

### 立即可用的扩展点
- **追加赛制事件**：在 `tournamentMatch.ts` 的 `TOURNAMENT_EVENTS` 数组追加一项即可，无需改 UI
- **追加预设数据集**：在 `simulation.ts` 的 `HISTOGRAM_DATASETS` 数组追加即可，扇形图 / 折线图 / 直方图 / 茎叶图自动支持
- **追加新模拟类型**：复用现有七系统（type → engine → runner → renderer → inspector → canvas → topbar）模板

### 已知限制 / 后续考虑
- 三人羽毛球赛泳道图当前固定展示第 1 次模拟的赛程；如需切换查看可在 Inspector 加「查看第 N 次模拟」选择器
- 双盒互换球当前限定每盒初始构成相同；如需「甲乙盒不同配置」需要扩展参数与状态空间
- AI 助手（`aiOperations.ts`）对新模拟类型的 mergeParams 已支持，但 `setSimulationType` 之外的其他 AI 操作未深度适配 tournamentMatch / boxSwapBalls
